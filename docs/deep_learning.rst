Deep learning based classification and segmentation
===================================================

The primary utility of QuST is to use the transcriptomic data as the biological basis for training deep learning models for
object categorisation and region segmentation on H&E images (paper, *DL-based image classification and segmentation with
QuPath*, Fig. 1c). QuST has functions that extract the single-cell H&E images for cell classification and the WSI patches for
region segmentation; the QuPath annotation and detection measurement tables can be exported as files, which serve as the image
labels for training. The result of the models can be analysed with the functions of the previous pages.

The deep learning module is based on PyTorch and performs image classification, which serves the cell categorisation and the
region segmentation. The training needs two inputs: an image set in a folder, generated by the image sampling of QuST, and the
detection/annotation measurement table of QuPath. QuST offers a wide range of neural networks, among them ResNet, VGG,
DenseNet and several variations of modern vision transformers (ViT).

Install the requirements of ``python/requirements.txt`` and set the preferences (:doc:`installing`) first.

Object classification
---------------------

In the experiment of the paper, the H&E image patches of each detected cell were acquired, the cell type from the ST data was
used as the label, and a ViT model was trained for the object classification (Figs. 10 and 11).

1. With the cells classified from the ST data (:doc:`loading`), select the annotation and run **Export Images for Object
   Classification**: it writes one image per cell, named by the object ID, into a folder.
2. Save the detection measurement table (**Measure → Show detection measurements → Save**) as a text file with the same name
   as the image folder (``sample1.txt`` for the folder ``sample1``). It needs the *Object ID* and *Classification* columns.
3. Train with ``python/train.py`` (see below).
4. Copy the model to the *Object Classification model directory* of the preferences. In another (or the same) image, select
   the annotation with the detected cells and run **Object Classification**, and choose the model.

Export Images for Object Classification
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Writes one image patch per detection object of the selected annotations into a folder (named by the object ID, in the
image format of the preferences).

.. list-table::
  :header-rows: 1
  :widths: 24 20 56

  * - Key
    - Default
    - Meaning
  * - ``dist``
    -
    - Destination folder (empty: ask)
  * - ``normalization``
    - true
    - Macenko stain normalization; the stain matrix is estimated on a sample of *sample size for H&E stain
      normalization* objects
  * - ``dontResampling``
    - true
    - Keep the pixel size of the image
  * - ``MPP``, ``samplingSize``
    - 0.21233 µm, 36 pixels
    - Pixel size and size of the patches when resampling
  * - ``allSamples``, ``samplingNum``
    - true, 0
    - Export all objects, or a random sample of this size

Object Classification
~~~~~~~~~~~~~~~~~~~~~

Classifies the detections of the selected annotations with a model of the *Object Classification model directory*. Uses
``classification.py`` and needs a pixel size. Result: the class ``objcls: <model>: <label>`` of each cell.

.. list-table::
  :header-rows: 1
  :widths: 24 20 56

  * - Key
    - Default
    - Meaning
  * - ``modelName``
    - first model
    - Model (``<name>.pt``, without the extension)
  * - ``includeProbability``
    - false
    - Also write ``objcls:<model>:prob:<label>`` for every label
  * - ``batchSize``
    - 1024
    - Batch size; lower it if the GPU runs out of memory
  * - ``maxThread``
    - 1
    - Maximum number of parallel threads (0: the QuPath setting)

Region segmentation
-------------------

The same is done for the regions: tiles of the H&E image, labelled by the annotated region (tumour, immune, stroma, adipose,
necrosis), are used to train a classifier, which is applied tile by tile to a slide (Figs. 12-14; the heat map of each tile shows
the probability that it belongs to a region, for several tile sizes).

1. **Export Images for Region Segmentation** writes a grid of tiles that cover the selected annotation, named
   ``<annotation ID>.<x>-<y>``.
2. Save the annotation measurement table (**Measure → Show annotation measurements → Save**) as a text file with the name of the
   folder: all tiles of an annotation take the class of that annotation.
3. Train with ``python/train.py``, copy the model to the *Region Segmentation model directory*, and run **Region Segmentation**
   on the annotation: the slide is divided into units of *Detection resolution*, each is classified, and one annotation per
   predicted region class is created.

Export Images for Region Segmentation
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Writes a regular grid of tiles that intersect the selected annotation, named ``<annotation ID>.<x>-<y>``. Parameters as
in the cell export, plus ``samplingStride`` (default 112 pixels; ``samplingSize`` is 224 and ``mpp`` replaces ``MPP``).

Region Segmentation
~~~~~~~~~~~~~~~~~~~

Classifies the tiles of the selected annotation with a model of the *Region Segmentation model directory* and creates
one annotation per predicted class.

.. list-table::
  :header-rows: 1
  :widths: 24 20 56

  * - Key
    - Default
    - Meaning
  * - ``modelName``
    - first model
    - Model (``<name>.pt``)
  * - ``detection_resolution``
    - 25 µm
    - Size of the unit of classification
  * - ``detection``
    - false
    - Save the probability distribution into the detections
  * - ``smooth_coeff``
    - 1.0
    - Gaussian blurring after the detection (smoothing coefficient)
  * - ``batchSize``, ``maxThread``
    - 128, 0
    - As in Object Classification

Training
--------

.. code-block:: bash

  python python/train.py my_model -i sample1 sample2 -d sample1.txt sample2.txt -o models -p 0.2125 -m resnet50 -n

``-p`` is the pixel size of the exported images (µm), ``-n`` states that the images were exported with stain normalization, ``-m``
is the network. It writes ``my_model.final.pt`` and the checkpoint of the best validation accuracy; copy one of them into the
model directory of the preferences. ``python train.py -h`` lists all options (batch size, epochs, learning rate, samples per
class, mixed precision, TensorBoard, ...).

The networks include ``resnet18/34/50/101/152``, ``wide_resnet50_2/101_2``, ``resnext``, ``densenet121/161/169/201``, ``vgg11`` to
``vgg19_bn``, ``vit_b_16``, ``vit_b_32``, ``vit_l_16``, ``vit_l_32``, ``vit_h_14``, ``swin_t/s/b``, ``maxvit_t`` and the
``vit-pytorch`` models (``dev_vit``, ``dev_cait``, ``dev_t2tvit``, and others). The images of a folder are taken as the images of
the objects named in the table: the part of the file name before the first dot is the object ID. The model file stores the
network, the labels, the pixel size, the image size, the image statistics and whether the images were normalised.

``python/classification.py`` is called by QuST itself (it applies a model, and estimates the stain matrix for the
normalization); it uses the GPU if there is one, and the CPU otherwise.
